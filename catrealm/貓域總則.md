## 詳細規章設計原則

1. 詳細規章的更改紀錄使用[Github](https://github.com/IceBearowob/Catnip-Server-Detailed-Rules)紀錄，以commit時間為更新時間依據
2. 詳細規章基於貓域規則，為貓域規則實例化
3. 詳細規章僅供參考
4. 詳細規章不屬於[貓域服務條款](https://catrealm.net/terms/)的一部分

## 管理原則
1. 所有貓域玩家與社群成員受貓域規則管理
2. @行政 應根據貓域規則管理，不得濫權
3. 貓域規則如有爭議，由 @行政 與 @system.cat 解釋

## 檢舉原則
1. 檢舉人必須是當事人之一
2. 檢舉應在[檢舉玩家](https://discord.com/channels/1546426739369058354/1546455677965180999)進行，或者私訊 @行政 進行"私下檢舉"
3. 檢舉時應寫明"檢舉內容"，如果發布貼文時有缺資料須限期補齊，否則不予受理
4. @行政 為檢舉案件主要受理、調查者
5. 檢舉程序:檢舉貼文發布->行政初次投票+案件調查->執行行政初次投票結果->玩家投票+玩家回饋(->行政再次投票)->結案
> 如果玩家投票=行政初次投票相同，按照行政初次投票結果結案  
> 如果玩家投票與行政初次投票不同，則行政會再次投票，最終以行政投票(討論)結果結案
1. 貓域得不受理貓域範圍外的檢舉案件
2. 涉及 @行政 相關(私下)檢舉案件由 @system.cat 受理

### 檢舉內容
應包含下列內容:
- 被檢舉人Minecraft ID 或 Discord User ID
- 檢舉原因
- 證據

### 私下檢舉
私下檢舉是一種半匿名檢舉方式，你可以將檢舉內容私訊給 @行政 ，行政受理後會將包含檢舉人的內容去識別化，並發布在[檢舉玩家](https://discord.com/channels/1546426739369058354/1546455677965180999)繼續檢舉程序

## 懲處與處置原則
1. @行政 依據貓域規則於合理範圍內懲處或處置玩家
2. 以下狀況 @行政 可以直接進行懲處判定:
> - 被檢舉人沒有綁定DC
> - 被檢舉人連續數天未上線
3. @行政 得視案件情況加重或減輕相關懲處或處置
4. 如果玩家觸犯多條規則，可以數罪併罰

## 申訴原則
1. 申訴應該在收到通知後7天內進行，申訴後行政方應在15天內給予回應
2. 資料不足者， @行政 或 @system.cat 得要求限期補正，如未能補正者則無效
3. 單一事由至少有一次的申訴機會
4. 申訴應依照申訴方法進行，並提供基本資訊

### 申訴方法
- 寄信到 `admin@catnip.live` 
- 在[詢問行政](https://discord.com/channels/1278590147193081947/1514810277827448882)新增貼文

### 基本資訊
申訴時必須提供:
- Minecraft ID
- 申訴原因

### 常見申訴內容
- UR玩家領地解凍申請
- 恢復原狀申請
- 損害賠償申請
- 懲處合理性申訴

## 模組與腳本功能使用原則
1. 不能改變原版機制，除貓域有提供除外
2. 不能造成伺服器負擔，或攻擊伺服器
3. 不能做出人做不出來的操作
4. 不能看到正常遊戲看不到的東西
5. 不會安裝需要伺服器端支援的模組
6. 不處理自行安裝模組造成的問題，並視為個人問題
7. 允許所有安裝在貓草啟動器內的模組
8. 模組/腳本功能使用應避免影響他人
9. 使用未允許或者未經過詢問的模組/腳本功能，請自行負責使用後果

## 公平交易原則

1. 雙方基於信任與合意而達成交易
2. 雙方交易時應確認好交易內容，並以可供查驗之方式各自紀錄
3. 如果任一方違反契約，守約方可以根據契約令違約方負擔責任，如果拒絕可以申請伺服器強制執行，伺服器方依契約有效部分處理
4. 在貓域範圍外的交易糾紛，原則上不予受理

## 一個帳號原則
1. 玩家只能使用Java或Bedrock帳號擇一登入伺服器遊玩
> 如果需要用手機登入，請進行[全域綁定](https://link.geysermc.org/)
2. 在Java版與Bedrock帳號進行物資、貓幣往來視為多重帳號
3. 經 @行政 發現疑似多重帳號並通知後，未能解釋或者依舊使用兩隻以上帳號遊玩者視為多重帳號
